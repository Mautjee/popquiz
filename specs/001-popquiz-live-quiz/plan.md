# Implementation Plan: PopQuiz Live Quiz Night

**Branch**: `001-popquiz-live-quiz` | **Date**: 2026-05-21 | **Spec**: `specs/001-popquiz-live-quiz/spec.md`

## Summary

PopQuiz is a self-hosted Go + HTMX web app for running live quiz nights. A host creates quizzes via an admin panel, players join teams via a room code, and a Team Head submits answers on behalf of the team. The app features real-time SSE updates, video round synchronisation, three question types (open, ranged, multiple choice), automatic and manual scoring, and Team Head auto-promotion. Data is persisted in SQLite with WAL mode.

## Technical Context

**Language/Version**: Go 1.22+

**Primary Dependencies**:
- github.com/go-chi/chi/v5 (HTTP router)
- github.com/mattn/go-sqlite3 (SQLite driver, requires CGO)

**Storage**: SQLite (file-based at $DATA_DIR/popquiz.db, WAL mode, foreign keys enabled)

**Testing**: Go standard testing package + internal/scoring pure function tests

**Target Platform**: Linux server (Docker container, golang:1.22-bookworm base)

**Project Type**: Web application (server-side rendered with HTMX)

**Performance Goals**: ~25 concurrent players, SSE updates within 2 seconds, video sync within 1 second

**Constraints**: Single binary, no external services, CGO_ENABLED=1 required, all multi-write DB ops in transactions

**Scale/Scope**: ~25 players across ~6 teams, self-hosted on Dokploy

No constitution violations — the project follows a single-binary, minimal-dependency approach. Go + SQLite + html/template + HTMX is the simplest stack that satisfies all requirements. The scoring package is pure functions per constitution principles of testability.
